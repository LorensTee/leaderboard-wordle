## 4. Authentication handoff

**Better Auth owns identity and sessions.** Google OIDC, session cookies, login/logout/session lifecycle, and the `/api/auth/*` endpoints are Better Auth's. The application owns authorization (roles, game ownership, admin rules) — never email comparisons scattered through routes.

- **SvelteKit hooks** (`../../src/hooks.server.ts`) resolve the session into `event.locals` for page-level behavior (signed-in header state, redirects). This is NOT an authorization source for the API.
- **Hono resolves sessions independently** — `authContext` in `../../src/server/middleware/auth.ts` calls Better Auth's `getSession` with the request's own cookies/headers on every API request (fast path: no `better-auth.session_token` cookie → `null` without a DB round-trip; boundary-matched cookie name). It never reads `event.locals` — the bridge does not pass them.
- **`requireAuth`** rejects unauthenticated requests with the standard `UNAUTHORIZED` error envelope (401, NG21) before any handler runs. It is mounted on `/api/game/*`, `/api/me/*`, `/api/admin/*` in `routes.ts` — Phase-1 routes under those prefixes are protected by default.
- **`c.get('auth')`** is the typed context value: `{ session, user } | null` (type `AuthContext`). Phase-1 handlers read identity from here — never re-query sessions, never read `event.locals`.
- **`/api/auth/*` exception** — deliberately NOT behind `requireAuth` (OAuth callbacks/redirects are cross-site by nature; Better Auth owns its own session/CSRF there). `authContext` still runs on those paths but is read-only and never rejects.
- **How Phase-1 game routes must use this boundary:** register routes in `routes.ts` (e.g. `app.post('/api/game/start', handler)`), read `c.get('auth')` for identity, check ownership/role invariants on the user object, return `AppError`-based envelopes. Nothing else is needed for authentication.
- **MUST NOT:** trust `event.locals` for API authorization; create a second session/authentication mechanism (no new session tables, no JWT schemes, no cookie re-implementations).

> Phase 1 must not create a second session/authentication mechanism.

## 6. Transaction/concurrency handoff

The tested contract (Architecture-v3 §588–637, NG9, M3; proven against live Neon):

- **Puzzle-first lock ordering:** every game mutation acquires the **puzzle row** lock (`SELECT ... FOR UPDATE`) BEFORE touching the game row. The puzzle row is the serialization point for daily-boundary operations (finalize vs guess).
- **Eligibility anchor:** `transaction_timestamp()` at the START of the transaction. NEVER use `clock_timestamp()` — it shares the same check-then-commit gap and makes acceptance depend on lock-wait timing. Invariant: a request whose transaction-start time is after `expires_at` can never pass the expiry check.
- **Expiry rule:** a guess is eligible only if the puzzle's `expires_at > transaction_start`. After eligibility, whoever acquires the puzzle lock first decides the outcome.
- **NG9 lock order A:** guess locks puzzle first → guess valid, completes/commits → finalization waits, then sees the updated state and converts only remaining ACTIVE games.
- **NG9 lock order B:** finalization locks puzzle first → commits `FINALIZED` → guess acquires the lock afterwards, re-reads (READ COMMITTED re-evaluation after lock wait), observes `FINALIZED`, is rejected, writes nothing.
- **M3 lazy activation:** if the cron missed activation, the first legitimate `POST /api/game/start` activates today's `SCHEDULED` puzzle in the SAME transaction under `FOR UPDATE`, with all guards: `puzzle_date` = current Asia/Manila date, `status = 'SCHEDULED'`, `expires_at > transaction_timestamp()`, no other ACTIVE puzzle for the date. Fail-closed + alert only when the row is absent (missing-puzzle invariant).
- **FINALIZED vs expiry:** finalization (Phase 3) must also run under the same puzzle-lock discipline; Phase-1 lazy activation stays as tested.

Phase-1 services (`../../src/server/game`, `../../src/server/puzzle` per the proposed tree) must implement `startGame`, `submitGuess`, `finalizePuzzle` preserving EXACTLY this contract. The integration tests encode it (see §7).

> Do not replace the tested transaction contract with a simpler implementation.

- **Wrangler/platformProxy:** dev bindings flow `.dev.vars` → dev `platformProxy` → `platform.env` → bridge cast → `c.env` → `getAuth`/`createDb`. The app reads env from bindings, NOT `process.env` (verified empirically at B4).
- **`NODE_ENV` auth behavior:** production is the default (Workers never set `NODE_ENV`). The dev fallback secret is selected only when `process.env.NODE_ENV ∈ {development, test}` (vite dev / vitest). Runtime-conditional and fold-independent (earlier fold-based assumptions were disproven — see B7). Do not change this policy.
- **XDG_CONFIG_HOME workaround:** this sandbox blocks `~/.config` writes, so local wrangler/dev commands run with `XDG_CONFIG_HOME="$PWD/.cache/xdg-config"` (gitignored). GitHub runners do not need this. `wrangler types` folds `../../.env`/`.dev.vars` into generated `Env` — so `types:check` is hermetic only without those files (CI condition); locally it fails by design while they exist. Never commit a `.dev.vars`-dependent `../../worker-configuration.d.ts`.
- **DATABASE_URL expectations:** the dedicated **non-production** Neon WebSocket connection string (`postgresql://…?sslmode=require`). Required for `db:migrate`, `test:integration`, and the CI `integration` job. Integration tests TRUNCATE the app tables (`guesses, games, daily_puzzles, answer_dictionary, "user"`) at fixture setup — the DB is reset-safe by user decision.
- **`auth:check`** writes its snapshot to `../../.cache` (auto-created since `690c6ec`); `../../.cache` is gitignored.
- **Never print or commit environment secrets.**

## 10. Word-list and answer secrecy handoff

- **Public valid-guesses artifact:** `../../src/lib/shared/data/valid-guesses.json` — sorted, unique, lowercase 5-letter words, generated from the canonical source. The browser MAY load it for local UX-only checking (Phase 1).
- **Canonical source:** `../../src/server/data/valid-guesses.source.txt` — committed, public, currently **20 words, explicitly labeled sample/fixture** (replace with the provenance-disciplined real import in Phase 1 per NG16; record upstream source/version/license/filtering in the header).
- **Build script:** `../../scripts/build-word-list.ts` (`bun run word-list`) — hard-fails on invalid entries and duplicates; deterministic output; pure functions unit-tested.
- **Private answer pool:** `../../scripts/seed` — gitignored `*.txt` inputs; only `../../README.md` is tracked. The pool lives in the DB (`answer_dictionary`), never in the repo, never in the client bundle.
- **Bundle secrecy check:** `../../scripts/verify-bundle-secrecy.ts` (`bun run verify:bundle`, CI gate after build) scans ALL build output (client + server) for pool words; unit test proves `../../src` never references the seed pipeline.
- **What Phase 1 may access:** the public valid-guess list (client + server), the hint letter (per architecture rules), game state.
- **What the browser must NEVER receive:** the answer, the answer pool, any hint that reveals the answer pre-start, `daily_puzzles.answerId` resolution, source maps containing server code, or any client payload containing the scheduled answer. **The Phase-1 game client may know the public valid-guess list but must never receive the answer.** Add a Phase-1 regression test asserting today's answer is absent from relevant client payloads.

## 11. Architecture boundaries

- **`../../src/server`** — all Hono/domain/backend code: routes composition, game logic (`../../src/server/game`), puzzle lifecycle (`../../src/server/puzzle`), leaderboard (`../../src/server/leaderboard`), profile (`../../src/server/profile`), admin (`../../src/server/admin`), auth, middleware, db. Never imports SvelteKit `RequestEvent`.
- **`../../src/lib`** — client application code, minimal FSD: `../../src/lib/app` (providers/theme) + `../../src/lib/shared` (`ui`, `lib`, `api`, `data`, `config`). Extract `features/`/`entities/` only when real reuse appears.
- **SvelteKit routes** (`../../src/routes`) — page/layout composition only, plus the API bridge. No business logic in `+page.svelte` beyond calling the API client.
- **`src/routes/api/[...path]/+server.ts`** must NOT contain: database queries, game logic, authorization logic, business rules. Platform translation only.
- **`../../src/server/routes.ts` owns** the composed Hono app: middleware order, route registration, `/api/auth/*` mount, type exports. The only composition point.
- **Game logic** → `../../src/server/game` (start/guess/finish services). **Puzzle lifecycle** → `../../src/server/puzzle` (activation, finalization, expiry helpers).
- **RPC typing:** create a typed client (`hc<AppType>`) in `../../src/lib/shared/api`; type-only imports of server types into client code; runtime imports of server code into the client bundle are forbidden (bundle-secrecy and answer-secrecy depend on it).

## 12. Decisions already made

These are decided. Do not reopen them unless a genuine contradiction, security flaw, or impossibility appears — then record the decision in `../contradictions-and-gaps.md`.

- **Better Auth owns identity/sessions** (§798) — no second auth system.
- **Hono auth helper** (`../../src/server/middleware/auth.ts`) — Hono independently authenticates; SvelteKit hooks are page-level only.
- **Neon WebSocket transaction path** (`drizzle-orm/neon-serverless` + `@neondatabase/serverless`) — required for interactive transactions; `drizzle-orm/neon-http` (one-shot) must not replace it (C6).
- **Puzzle-first locking** (NG9) — the puzzle row is the serialization point; both lock orders tested.
- **Manila timezone** (NG1) — Cloudflare cron `0 16 * * *` (UTC), `puzzle_date` as DATE, `expires_at = (puzzle_date + 1) AT TIME ZONE 'Asia/Manila'`.
- **`transaction_timestamp()`** is the eligibility anchor — never `clock_timestamp()` (NG9).
- **CSRF fail-closed** (NG4) — custom Origin/Sec-Fetch-Site middleware; headerless mutations and `Sec-Fetch-Site: none` rejected; `/api/auth/*` exempt because OAuth callbacks are cross-site.
- **Token-column decision** (B8) — `account` token columns are Better Auth-managed core-schema fields, kept nullable and inert; the app requests OIDC scopes only (no `access_type=offline` → no refresh token); documented in Architecture-v3 §Session/cookie strategy.
- **Pinned Better Auth CLI** (`auth@1.7.1` exact) — `auth@latest` drift was the original problem; regeneration must stay deterministic.
- **Mandatory integration CI gate** — the `integration` job FAILS when the non-prod `DATABASE_URL` secret is missing (no silent skip).
- **Word-list duplicate handling** — duplicates hard-fail the build (they were silently deduped before B8, contradicting the documented rule).
- **Dev-secret policy** — production default; dev fallback only under `NODE_ENV ∈ {development, test}`; missing secret in production → throw (B7 security review).
- **`/api/auth/*` exemption** from CSRF/requireAuth — Better Auth owns those endpoints.

## 15. Phase-1 risks / watch-outs

Mistakes a fresh coding agent is most likely to make:

- **Trusting SvelteKit `locals` for API authorization** — Hono must authenticate independently (`c.get('auth')`).
- **Exposing the answer** through API responses, load data, hydration payloads, client bundles, or errors.
- **Importing server runtime code into client code** — breaks answer secrecy; type-only imports only.
- **Breaking puzzle-first lock ordering** — the puzzle row must be locked before the game row on every mutation.
- **Using `clock_timestamp()` instead of `transaction_timestamp()`** — the tests encode the anchor.
- **Accepting client timing** — `started_at`/`completed_at`/`completion_time_ms` are server-computed.
- **Naive duplicate-letter evaluation** — Wordle's classic bug; exhaustive `evaluateGuess` unit tests required.
- **Allowing a seventh guess** — `UNIQUE(game_id, guess_number)` + server-side max check.
- **Forgetting concurrent start idempotency** — `UNIQUE(user_id, puzzle_id)` + return the existing game.
- **Allowing completed games to mutate** — terminal states are immutable; `completionTimeMs` set exactly once.
- **Weakening CSRF** — fail-closed behavior is deliberate; `/api/auth/*` exemptions are the only exceptions.
- **Adding React packages** — only Svelte variants.
- **Changing the Neon driver** — `neon-serverless` WebSocket path only.
- **Creating an alternate API composition point** — `../../src/server/routes.ts` is the only one; the bridge stays thin.
- **Silently skipping integration tests** — CI fails without the secret by design; run them with the non-prod DB.
- **Regenerating the Better Auth schema with an unpinned CLI** — use the pinned `auth@1.7.1`; `auth:check` gates it.
- **Changing architecture without recording a decision** — every deviation goes into `../contradictions-and-gaps.md`.
- **Running `types:check` locally with `../../.env`/`.dev.vars` present** — it fails by design in that state; use the CI condition or expect the fold.
- **Re-pointing the lock-order tests with weaker assertions** — the contract must be preserved, not approximated.

## 17. Handoff invariants

- Better Auth is the ONLY identity/session system; Hono authenticates independently; never trust `event.locals` for API authorization.
- The answer and answer pool never reach the browser; `verify:bundle` stays green; client gets only the public valid-guess list.

- One game per user per puzzle (UNIQUE + idempotent start); guess numbers sequential (UNIQUE); no seventh guess; completed games immutable.
- Server is authoritative for timing, evaluation, expiry, and feedback; client input is always re-validated.
- All API errors use the NG21 envelope; CSRF stays fail-closed; `/api/auth/*` exemptions unchanged.
- `../../src/server/routes.ts` is the only Hono composition point; the bridge stays thin; `../../src/server` never imports SvelteKit `RequestEvent`.
- Neon WebSocket driver path unchanged; migrations/journal committed; integrity of `auth:check` (pinned CLI) and CI gates preserved (integration job mandatory).
- Tests encode the transaction contract — re-point them at services, never weaken them.
- No React dependencies; framework packages are the Svelte variants.
- Record every architectural decision in `../contradictions-and-gaps.md`.
